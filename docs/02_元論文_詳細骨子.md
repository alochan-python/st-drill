# 設問イ｜第2章 基幹システムの刷新方針

## 2.1 刷新方針の必要性と経営上の有効性

**起動キー：【え】観・方・検・理・経・投【/え】**

> ・観：現場観察・工数実測 → As-Is／To-Be → Excel全項目確認・訂正がボトルネック
>
> ・方：KGI＝SLA安定化・品質平準化・属人化低減／KPI＝SLA遵守率・処理時間・差戻し率
>
> ・検：業務・データ・アプリ・技術／運用の観点で実現性、運用継続性・内部統制リスクを検討
>
> ・理：残業・応援コスト増／有識者不足／Excel確認ボトルネック
>
> ・経：SLA未達→出荷・計上遅延、誤入力→欠品・誤出荷・差戻し → 基幹業務安定化は経営上有効
>
> ・【え】投：PoC10帳票で確認・訂正時間約3割削減。総額約5,000万円を一括執行せず段階Go／No-Go【/え】
>
> ・【え】　　本番初期対象でもPoC同等の約3割削減 → 適用拡大。本番後はSLA・差戻しを継続評価、未達なら追加投資見送り【/え】

## 2.2 刷新方針

**起動キー：受・前・第一・第二・第三**

> ・【え】受：受注データ正規化・一元管理 → 後続連携。前工程を一つの仕組みとしてIT＋業務で再設計する方針【/え】
>
> ・【え】第一＝業務標準化：本番安定後に大阪集約／帳票定義・標準項目・適用優先度を標準化【/え】
>
> ・第二＝IT刷新：Excel確認廃止 → DB正規化 → 確認画面 → 誤読・例外だけ修正
>
> ・訂正データ → RPA後続入力／ログ・訂正履歴一元化→内部監査／品名揺れはルールベースで品番変換
>
> ・第三＝段階展開：PoC → 本番 → 他部門、各段階Go／No-Go、効果確認済み帳票から拡大

## 2.3 重要と考え工夫したこと

**起動キー：精・PoC・本・保**

> ・精：OCR精度だけでなく確認工数と運用性を重視
>
> ・PoC：確認工数・SLA寄与＋監視・リトライ・二重投入防止・障害時退避
>
> ・【え】　　対象10帳票の1件当たり確認・訂正時間を約3割削減【/え】
>
> ・【え】本：本番は帳票を段階切替、新旧並行稼働を計画／問題時の切戻し手順【/え】
>
> ・【え】保：帳票定義・入出力項目・画面レイアウト標準化→共通部品化する方針／運用手順書整備【/え】
